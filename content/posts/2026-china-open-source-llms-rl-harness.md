从 2026 年初开始，国内开源大模型的编程、推理、工具调用和自主执行能力提升得非常明显。一个值得追问的问题是：这些进步，究竟来自更丰富、更高质量的原始训练数据，还是来自 **Harness Engineering**（智能体执行框架工程）？

**我的判断是：核心变化不是二选一，而是训练范式的重心发生了转移。强化学习、可验证任务环境、高质量合成数据、架构效率和 Harness Engineering 开始组成一个相互促进的系统。** 其中，对编程和 Agent 能力提升最直接的驱动力，越来越多地来自后训练及可验证环境，而不是仅仅扩大互联网文本语料。

## 一、一个关键证据：底座不变，能力也可以显著提升

2026 年 8 月，智谱发布 GLM-5.3。官方明确指出，**GLM-5.3 使用与 GLM-5.2 相同的基础模型，性能改善来自后训练**。按其公布的内部 Z.ai Code Bench，代码能力相对改善约 50%；DeepSWE v1.1 的报告分数从 46.2 提升到 66.9。[1]

这个案例非常重要：如果底座的预训练权重相同，那么这些提升就不能简单归因于“又读了更多互联网原始资料”。它说明，已有基础能力还可以通过强化学习、任务难度、奖励设计和训练环境得到进一步释放。

这里应当保留一个限定：**50% 是厂商内部代码基准的相对改善，不代表所有能力统一提高 50%，不同基准与 Harness 之间也不可直接横向比较。**

## 二、真正变化的，是数据的形态

在传统语言模型的预训练中，数据主要是网页、书籍、代码、论文等静态语料；监督微调则通常让模型模仿优质示范回答。这些数据仍然重要，但对“自主修复一个真实软件仓库”之类的任务，单纯模仿答案并不充分。

新的训练样本更接近一个完整的、可验证的交互过程：

> **任务描述 → 模型提出行动 → 执行代码或调用工具 → 环境返回结果 → 测试验证 → 奖励和纠错**

MiniMax 在 2026 年 1 月介绍 M2.1 后训练时，就披露了从真实 GitHub PR 和 Commit 中提取任务、搭建可运行 Docker 环境、提取与生成测试的流程，并形成超过 14 万种任务变体。[2]

这类数据的价值不单是“文字质量高”，更在于能够回答：**模型究竟有没有把事情做成？** 当答案可以被编译器、单元测试、数据库状态、浏览器或业务规则验证时，强化学习可以持续利用反馈调整模型，而不是只靠人类逐条标注正确答案。

因此，2026 年所谓的“数据质量提升”，更准确地说是**从静态知识语料，扩展到环境交互轨迹、可验证结果和不断生成的新任务**。

## 三、强化学习从解题走向执行真实工作

2025 年以 DeepSeek-R1 为代表的工作，让推理强化学习受到广泛关注。到了 2026 年，显著的变化是 RL 逐渐从数学题、逻辑题，扩展到代码工程、工具使用、浏览器操作、多智能体协作和长时任务。

有几条清晰的技术路线：

- **Qwen3.5：扩展 RL 的任务与环境。** 阿里在 Qwen3.5 发布材料中明确强调，其后训练改进主要来自对多类强化学习任务和环境的大规模扩展。[3]
- **MiniMax M2.5：把各种 Agent 执行框架纳入训练。** 其 Forge 系统通过标准化的交互协议，将底层训练引擎与 Agent 框架解耦，使模型可以在大量复杂环境中接受强化学习，而不是绑定某一种固定的执行工具。[4]
- **Kimi K2.5：训练模型进行多智能体协调。** 通过 Parallel-Agent Reinforcement Learning（PARL），模型不仅执行单个子任务，还学习何时拆分工作、怎样协调多个子 Agent。[5]

从工程角度看，过去常常是**人编排工作流，模型填写其中一个步骤**；现在则越来越倾向于**训练模型自己决定下一步行动、使用哪个工具，以及结果是否足够好**。

## 四、架构效率是另一个重要推动力

后训练并没有使预训练或模型架构失去价值。

例如，GLM-5 相比 GLM-4.5，将预训练 Token 规模由约 23 万亿提高到 28.5 万亿，说明扩充底座仍然重要。[6]

DeepSeek-V4 则展示了另一条方向：通过 Compressed Sparse Attention 与 Heavily Compressed Attention 组成的混合注意力机制，降低长上下文推理的计算与缓存成本。其技术报告称，在 100 万 Token 上下文条件下，V4-Pro 单步解码所需计算量约为 V3.2 的 27%，KV Cache 约为 10%。[7]

这些指标并不意味着“模型本身的所有智能指标直接提高了同等比例”，但**更低的推理成本会让更长的思考、更多轮工具调用和更复杂的训练任务成为可负担的工程选项**。模型架构、算力利用率和 RL 训练规模由此相互影响。

## 五、Harness Engineering：让模型已有能力真正转化为任务完成率

这里必须区分两个概念：

**模型能力**，指模型权重内部学到的知识、推理、工具选择及行动策略；**Harness**，指模型外部负责连接工具、管理上下文、执行命令、保存状态、验证结果和安排循环的系统。

比如同一个模型，通过聊天窗口回答“如何修复 Bug”，与通过 OpenCode、文件系统、终端、测试框架反复操作一个真实项目，最终成果可能完全不同。这并不一定说明模型权重变强了，而是 Harness 把它已有的能力更有效地释放出来。

2026 年的 *Agentic Harness Engineering* 研究提供了一个有启发的控制变量案例：在基础模型保持不变的情况下，通过迭代改造智能体框架，Terminal-Bench 2 的 Pass@1 由 69.7% 提升到 77.0%，增加 **7.3 个百分点**。[8]

但不能因此得出“框架越复杂越好”的结论。额外的工具、角色和状态管理可能带来调用成本、错误传播、上下文污染与调试困难。真正优秀的 Harness，往往是把失败模式分析清楚后，针对性地增加最少而有效的控制。

**更值得注意的是，训练时的 Harness 与部署时的 Harness 正在发生融合。** 微软研究院的 Agent Lightning v1.0，就是尝试让 Agent 在真实执行框架中运行并接受 RL 训练；其披露的实验在约 6000 个训练样本条件下，将 Qwen3.5-9B 的 SWE-bench Verified Pass@1 从 41.8% 提升到 56.4%。[9]

## 六、我对这轮技术进步的排序

下表是针对**编程与 Agent 能力**的定性判断，不是通过统一消融实验得出的精确贡献率；对知识问答、视觉理解或科学推理，不同因素的排名可能不同。

| 技术因素 | 相对重要性 | 核心贡献 |
| --- | --- | --- |
| Agentic RL 与后训练 | 极高 | 学会行动、规划、验证与纠错 |
| 可验证任务环境和合成数据 | 极高 | 提供大规模、可信的训练反馈 |
| 模型架构与训练基础设施 | 很高 | 降低长上下文与复杂推理成本 |
| Harness Engineering | 很高 | 将模型潜力转化为真实任务完成率 |
| 更大规模的原始预训练数据 | 仍然重要 | 构建广泛知识与基础表征 |

这些因素并非彼此独立。例如，没有可靠的执行环境，RL 就难以获得有效奖励；没有高效的模型架构，大规模长轨迹 RL 会过于昂贵；没有好的部署 Harness，即使模型权重很强，也可能无法稳定完成任务。

## 七、下一阶段真正值得关注的竞争优势

过去的竞争重点是“谁能训练更大的模型、谁有更多文本和算力”。下一阶段，我更关注以下能力：

1. **自动制造困难任务。** 从真实问题生成新的、分布足够广的训练情境。
2. **自动验证任务完成。** 不依赖模型自己打分，而是尽可能采用测试、执行结果和外部事实。
3. **低成本地大规模试错。** 提升 RL rollout、训练并行度和推理效率。
4. **让使用反馈回到训练。** 将真实 Agent 在代码、浏览器、企业业务系统里的成功和失败，转化为下一轮可验证样本。

其中第四点最有想象空间：**部署中的 AI 不只是回答问题，还会为未来训练产生有价值的交互轨迹。**

这可能形成一个持续增强的飞轮：

> 更强模型 → 完成更复杂任务 → 产生更多可验证轨迹 → 改善后训练 → 得到更强模型

不过，这不等于已经实现完全自主的递归自我改进。环境构建、目标设定、奖励漏洞、数据污染、测试覆盖和训练稳定性仍然需要严格的工程与人工把关。

## 八、对本地模型使用者有什么启示？

如果在本地使用 **LM Studio + Qwen + OpenCode**，不应仅以模型在聊天界面的对话质量判断其实际能力。更有价值的是分别测量三层：

- **底座表现：** 固定问题集，在统一推理参数下考察知识、推理和代码生成质量；
- **接口与模板：** 检查 Chat Template、系统提示词、上下文长度、工具调用协议及采样设置，避免 API 接入错误导致能力退化；
- **执行框架：** 在固定仓库和任务集上，记录真实完成率、总耗时、Token 成本、测试通过率和失败恢复能力。

这三个层次分开测量，才能知道是模型真的进步了，还是 Harness 更善于发挥它的潜能。

## 结语

**2026 年国内开源大模型的跃升，不应被理解为“原始数据革命”与“Harness 革命”的二选一。它更像一次以可验证任务环境和强化学习为中心、由模型架构与智能体工程共同推进的训练范式升级。**

数据依然是基础，但竞争正在从“让模型看过更多内容”，转向“让模型在可反馈的世界中做过更多事情，并真正学会把事情做成”。
